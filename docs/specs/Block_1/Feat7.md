# Feat7 · Availability day view (Booking-2)

**Block:** B1 · **Backlog ID:** Booking-2 · **Labels:** `block-1`, `booking`

## Goal

A day view of lanes × 30-min slots shows which slots are free and which are booked, and members book from it. The read path teaches no-tracking projections, GiST index use, `EXPLAIN ANALYZE` and connection pooling.

## Scope

- `GET /api/clubs/{clubId}/availability?date=YYYY-MM-DD` (`ClubMember`):
  - For each lane: the slots inside its opening hours on that club-local date.
  - Slot state: `free`, `booked` or `past`. `mine: true` marks the caller's own bookings.
  - One no-tracking projection query, with no entity materialization. Bookings are selected by `period && <day range>`.
- Index: the exclusion constraint's GiST index on `(lane_id, period)` ([Feat6](Feat6.md)) serves the query.
  - Checked with `EXPLAIN (ANALYZE, BUFFERS)` against ≥ 50,000 synthetic bookings, generated by a local-only script (not the staging seed). The plan goes in the learning log.
- Connection pooling: Npgsql `Maximum Pool Size` is set so that pool size × maximum replicas stays below the server's `max_connections`. Documented.
- Angular `/clubs/:id/day/:date`:
  - A grid of lanes × slots, with a date picker.
  - Selecting a free slot books 1 or 2 slots through [Feat6](Feat6.md).
  - On `409`, the UI shows "just taken" and refreshes the grid.

## Acceptance criteria

- [ ] The grid shows every lane's slots for the date in club-local time, within the lane's opening hours.
- [ ] Booked slots show as booked; own bookings show as mine; past slots can't be booked.
- [ ] Booking a free slot from the grid succeeds, and the slot shows as mine without a page reload.
- [ ] A slot taken by someone else in the meantime shows the message and a refreshed grid.
- [ ] The availability endpoint runs one SQL statement (EF Core log), and its plan uses the GiST index (`EXPLAIN ANALYZE` in the learning log).
- [ ] The response contains no other member's identity.
- [ ] During the measurement, `pg_stat_activity` shows no more API connections than the configured pool size.

## Definition of Done

- [ ] Merged to `main` by pull request with CI green.
- [ ] Deployed to `staging` through the pipeline; the smoke tests passed; one booking made through the grid on `staging`.
- [ ] Tests: unit tests for slot generation from opening hours; integration tests for the slot states.
- [ ] Learning-log entry written (query plan, pool sizing).
